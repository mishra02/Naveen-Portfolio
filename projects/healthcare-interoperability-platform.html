Healthcare Interoperability Integration Platform

A backend-first integration platform prototype for accepting healthcare payloads, storing them reliably, and transforming JSON into HL7 text for downstream processing.

Scope note: This is an in-progress personal build. The current focus is reliable message intake and JSON-to-HL7 transformation. FHIR, Nabidh, DHA, and other adapters are broader platform goals and should not be read as completed integrations.

Project overview

This in-progress project is being developed as a scalable integration foundation. The current implementation accepts inbound JSON through an API, stores messages in SQL Server, and processes them asynchronously through a background worker. The current milestone adds an Hl7Message field populated from the stored JSON payload. Support for broader standards and regional integrations is a planned direction, not represented here as already completed.

My role and responsibilities

  • Designed a Clean Architecture solution using .NET 8 and separate API, Application, Domain, Infrastructure, and Worker projects.
  • Implemented an inbox API that accepts and persists JSON payloads.
  • Used Entity Framework Core and SQL Server for persistence and migrations.
  • Implemented idempotency and duplicate-request handling.
  • Implemented atomic message claiming, processing states, claim recovery, retry/error handling, and background processing.
  • Added a new Hl7Message database column and is working on populating it from PayloadJson in the worker.
  • Defined HL7, FHIR, and regional integrations such as Nabidh/DHA as broader platform goals; these should be described as roadmap items until implemented.

Capabilities and contribution

  • Established an asynchronous inbox-processing foundation.
  • Added reliability controls for duplicate submissions and worker claiming.
  • Created a foundation for healthcare message transformation and future interoperability adapters.
